# ViceModVI - Xbox

ViceModVI is a desktop tool for exploring, previewing, exporting, and editing local game assets. The first edition focuses on Xbox Series RPF9 and TTPF files. The workflow is designed for modders who have a readable copy of the files.

**Current status.** The Windows viewer and CLI support folder browsing, preview, OBJ and DDS export, and staged texture edits. The CLI can write verified offline copies of compatible RDS5 pools and selected RPF9 dictionaries. In-game compatibility is pending.

## Workflow

1. Open an RPF, a TTPF, or a working folder. Import an existing inventory or generate the catalog on first open.
2. Search by recovered name, type, hash, file, or offset. Show whether a name comes from the asset, a reference, or an alias generated by the application.
3. Preview a texture or a model. Selecting a material shows the textures it uses, where they are stored, and which other assets are known to reference them.
4. Export one or more assets using the context menu. Open **Edit texture** to import a replacement, compare it on the mesh, export the DDS, or revert the edit in the current session.
5. Use the CLI to generate verified copies. Record in-game compatibility for each version and platform after a real test.

## First-release scope

| Area | Initial release | Expansion |
| --- | --- | --- |
| Catalog | Textures and models, search, and a persistent index | Audio, animation, VFX, and other types as readers become available |
| Preview | Image, channels, and available mips. Model with material and resolved textures | Variants and component assembly where references can be demonstrated |
| Export | Individual DDS, PNG and OBJ exports, plus batch export of selected assets | Complete materials |
| Editing | Stage replacements and compare on the mesh. Convert and export a compatible DDS | TTPF and fixed-size RPF9 copies through the CLI, with runtime testing tracked by platform |

DDS preserves the format and mips when the reader can provide them. PNG is an editing output for the selected image. Every export must be traceable to its source file and asset.

## Responsibilities

- **Catalog.** Imports inventories and manifests generated by available tools. Persists locators and types while keeping game files outside version control.
- **Readers.** Read the selected entry by offset or identifier and return data ready for export or preview. An asset may span several segments.
- **References.** Links models, materials, and textures using identifiers or observed references. Returns evidence and ambiguous candidates so the viewer can distinguish them.
- **Editing.** Keeps replacement textures in the current desktop session. Export a staged DDS to keep it as a separate file. The CLI can generate archive copies for compatible storage profiles.
- **Interface.** Shares catalog and editing code across platforms. Xbox is the first backend. Other planned editions are ViceModVI - PS5 and ViceModVI for PC. Publish coverage separately for each platform.

## Data limitations

The TSV identifies ranges detected during scanning. Recovered names and types come from the assets and manifests. The original RPF9 path table remains unresolved. A compressed block can be only part of an asset. Preserve TTPF hashes as identifiers when readable names are unavailable.

The sample walkthrough opens **one local model**, follows **one diffuse texture** from its material into a separate folder, and shows the replacement on the mesh before reverting it.

## Build

Use Windows with the .NET 10 SDK and Windows Desktop Runtime. The CLI and WPF viewer reference the separately checked out rpf9-explorer Core reader at Leonida's pinned revision. Core targets .NET 8 and restores BCnEncoder.Net 2.3.0. Python 3 is used for the sample inventory. [rpf9-explorer by breadbbbb](https://github.com/breadbbbb/rpf9-explorer) · [Leonida's third-party tree](https://github.com/ItsNotRexed/Leonida/tree/main/third_party)

From the ViceModVI-XBOX root, use the initialized sibling checkout at `../Leonida/third_party/rpf9-explorer`. If the submodule directory is empty, fetch the pinned revision separately and set `RpfExplorerCore` as shown. The repository contains only ViceModVI source. The pinned upstream revision has no repository-level license file, so keep the upstream source and binaries out of distributable ViceModVI artifacts pending permission.

```powershell
git clone --no-checkout https://github.com/breadbbbb/rpf9-explorer.git .local/rpf9-explorer
git -C .local/rpf9-explorer checkout --detach 48557ead00601d3757ba12b894f2595c4faad2a5
$env:RpfExplorerCore = (Resolve-Path .local/rpf9-explorer/Core/RpfPreview.Core.csproj).Path
dotnet build src/ViceModVI.Desktop -c Release --artifacts-path .local/build
$cli = (Resolve-Path .local/build/bin/ViceModVI/release/ViceModVI.exe).Path
$viewer = (Resolve-Path .local/build/bin/ViceModVI.Desktop/release/ViceModVI.Desktop.exe).Path
```

The first build restores dependencies from NuGet, including the shared Magick.NET Q8 raster decoder version 15.1.0. Open an RPF or TTPF with **Open file**, or scan a directory with **Open folder**. Select folders or archives in the tree to scope the list and its search. The source path appears in the browser and in search result tooltips. The status bar names the archive and reports scanning and validation progress. ViceModVI reuses each source index from its local app data cache if the size, timestamp, and sampled bytes match. Closing the window during indexing cancels the current read and keeps completed source indexes. Use `catalog OUTPUT --fresh INPUT` to measure a scan without the cache. Optional TSV imports also add known stored byte ranges. [Magick.NET package](https://www.nuget.org/packages/Magick.NET-Q8-AnyCPU/15.1.0)

### Expanded model coverage

The model helper uses the inventory and drawable reader from a sibling checkout named `gta6-resource-tools`. Use the pinned source revision and the patch bundled with ViceModVI, which adds indexing progress, bounds memory use on large archives, reads zlib sequences above 16 MiB (as in `audio.rpf`), and accepts the `9FPR` headers of `levels.rpf` and `core_bvh4.rpf`. Apply the patch once to a clean checkout. After building .NET, run these commands from the ViceModVI repo root on Windows with Rust and the MSVC build tools:

```powershell
git clone https://github.com/cayetanobp/gta6-resource-tools.git ../gta6-resource-tools
git -C ../gta6-resource-tools checkout --detach 3e6f69cb840112dc7b198f2e23a14520e493dc23
$readerPatch = (Resolve-Path tools/model-reader/gta6-resource-tools-progress.patch).Path
git -C ../gta6-resource-tools apply $readerPatch
cargo build --locked --release --manifest-path tools/model-reader/Cargo.toml --target-dir .local/model-reader
Copy-Item .local/model-reader/release/vicemodvi-models.exe (Split-Path $viewer)
Copy-Item .local/model-reader/release/vicemodvi-models.exe (Split-Path $cli)
```

Package the helper alongside the desktop or CLI executable when publishing. Without it, ViceModVI uses its existing model reader. The helper inventories each RPF first, lists individual drawables, and supplies candidate offsets to the existing readers for compatible resources. It decodes drawable geometry on selection or export. Additional drawables provide static geometry and UVs. For supported material layouts the viewer looks up diffuse textures by their full native key, including textures from TTPF files in the open catalog.

## Reproduce the sample

Use Xbox Series build 1.0.2.1 and the supplied `core_restofworld/core_restofworld` folder. The expected RPF SHA-256 is `a28e53eee58e0b7541bee699ca0136d7a8402934984fe1d12d573905a24da5f0`. Run these commands from the repository root after building. A compatible `rpf9-index` TSV can replace the conversion below.

```powershell
$sample = (Resolve-Path core_restofworld/core_restofworld).Path
$out = Join-Path $env:TEMP ("vicemodvi-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $out | Out-Null
$rpf = Join-Path $sample 'core_restofworld.rpf'
$index = Join-Path $out 'index.tsv'
$catalog = Join-Path $out 'catalog.json'
python -I ../Leonida/tools/rpf9_carve.py $rpf $out --index-only
& $cli inventory-tsv (Join-Path $out 'index.json') $index
& $cli catalog $catalog --inventory $index $sample
& $cli verify $catalog
& $cli read $catalog '0:range:4010' (Join-Path $out 'range.bin')
& $cli read $catalog '0:range:4010' (Join-Path $out 'wrong-source.bin') (Join-Path $sample 'data/ttdb/textures_loose.ttpf')

$mesh = Join-Path $out 'reference.obj'
$dds = Join-Path $out 'reference.dds'
& $cli export $catalog '0:model:203F010' $mesh
& $cli export $catalog '3:ttpf:0' $dds
& $cli inspect $mesh
& $cli inspect $dds
& $cli resolve $catalog '0:model:203F010'
& $cli resolve $catalog
```

The second raw read command above intentionally returns an error. To reproduce the bounds rejection, copy the catalog JSON and set the `range.offset` of `0:range:4010` to the RPF's byte length. Run the same raw read with the edited catalog and a fresh output path. Ordinary entry reads verify length, modification time, and up to eight 4 KiB samples before seeking. The `verify` command and raw reads with an explicit alternate source validate the full SHA-256.

Import Leonida `rpf9dump` manifests with `& $cli import-manifest $catalog SOURCE_ID MANIFEST_JSON`. RPF manifests use `Items` with `Offset`; TTPF manifests use `Textures` with `Index` and `AssetKey`. Native types still come from structure validation. To reproduce an ambiguous link, copy `data/ttdb/props/ttdb_props.ttpf` outside the sample and supply that copy after `$sample` when building a second catalog. Resolve the same model against that catalog.

### Local replacement workflow

1. Run `& $viewer $sample`, or open the sample using **Open folder**. Select `core_restofworld.rpf` in the tree and search for `0:model:203F010`. Select the model and the mesh using shader 1. The Inspector shows the confirmed diffuse texture.
2. Right-click the model to export it. Use **View linked texture** to select entry 90 in `data/ttdb/props/ttdb_props.ttpf`. Right-click the texture to export DDS or a PNG preview. Ctrl-select more entries to export a batch to one folder.
3. Expand **Edit texture** and import an image. Use **Original** and **Replacement** to compare on the selected texture or mesh. Right-click the texture and choose **Export staged DDS** to keep the imported bytes. Select **Revert replacement** to clear that edit. Use **Open file** to browse the pool on its own.

The importer stages supported DDS files byte for byte. Raster inputs, including PNG, JPEG, BMP, TGA, TIFF, WebP, GIF, PSD, AVIF, HEIF, EXR and HDR, are decoded to a one-mip 8-bit BGRA DDS. The first image or composite is used for animated, paged, or layered inputs. Some DDS encodings can use the raster decoder as a fallback. OBJ export includes static geometry and available UVs. The viewer applies the confirmed diffuse image of the selected material. Native shader effects, blending, and animations require separate support.

### Experimental TTPF copy

Use `& $cli pool-profiles $catalog 3` to list writable entries in the sample loose pool. Stage an image on entry 4 and select **Convert for TTPF export** to review the imported and output dimensions, DXGI format, and mip counts. The dialog reports conversion warnings or the specific unsupported storage or encoding limitation. Exporting creates a DDS and keeps the imported DDS available for preview.

The CLI uses the same conversion. A compatible DDS passes through unchanged. If only mip levels are missing and the format matches, conversion preserves the supplied mip bytes and generates the missing levels. Encoding supports common uncompressed DXGI layouts and BC1, BC2, BC3, BC4 UNORM, BC5 UNORM, and BC7. Compatible signed BC and BC6H DDS files can pass through. The pool writer requires the original dimensions, so a dimension mismatch requires explicit confirmation in the viewer or `--resize` in the CLI.

The CLI refuses an existing destination unless `--overwrite` is supplied. Before publishing the output, the writer reopens the pool, compares the converted DDS payload and a neighboring entry, and verifies the original fingerprint. An explicitly overwritten source refreshes its catalog fingerprint.

```powershell
$full = Join-Path $out 'writable.dds'
$edit = Join-Path $out 'edited.dds'
& $cli export $catalog '3:ttpf:4' $full
$bytes = [IO.File]::ReadAllBytes($full)
$bytes[$bytes.Length - 1] = $bytes[$bytes.Length - 1] -bxor 1
[IO.File]::WriteAllBytes($edit, $bytes)
& $cli write-pool-copy $catalog '3:ttpf:4' $edit (Join-Path $out 'edited.ttpf')
```

To test conversion, pass a PNG, TGA, or incompatible DDS to `convert-for-ttpf` for a standalone DDS, or to `write-pool-copy` to produce a TTPF. Use `--resize` when the image dimensions differ. Entry 0 in the same pool demonstrates a storage limitation because its source exposes three of eight mips. RDS5 in-game compatibility requires a test on the exact Xbox build.

### Experimental RPF9 copy

The CLI can replace a 2D texture in a recovered standalone dictionary when every changed zlib segment can be encoded at its original packed length. The writer publishes a new file after reopening it, recovering the selected DDS, verifying a dictionary neighbor when one exists, and comparing every byte outside the replacement segments. The original directory and archive size remain intact.

```powershell
$target = '0:dictionary:680010:texture:0'
$untouched = Join-Path $out 'rpf-source.dds'
$edited = Join-Path $out 'rpf-edit.dds'
$copy = Join-Path $out 'core_restofworld-test.rpf'
& $cli export $catalog $target $untouched
$bytes = [IO.File]::ReadAllBytes($untouched)
$bytes[152] = $bytes[152] -bxor 1
[IO.File]::WriteAllBytes($edited, $bytes)
& $cli write-rpf-copy $catalog $target $edited $copy
$copyCatalog = Join-Path $out 'rpf-copy.json'
& $cli catalog $copyCatalog --fresh --inventory $index $copy
& $cli export $copyCatalog $target (Join-Path $out 'rpf-reopened.dds')
Get-FileHash $edited, (Join-Path $out 'rpf-reopened.dds')
& $cli verify $catalog
```

Passing the untouched DDS to `write-rpf-copy` with a fresh destination reproduces the original archive SHA-256. A real Xbox Series 1.0.2.1 test of loading the edited copy and restoring the original is pending.
